# 家庭事项记录 · 飞牛 NAS Docker 部署包

以家庭为单位的私有记录系统：**学习成长轨迹 / 学生花销 / 家庭账本 / 笔记本** 四个一级模块，各自带二级目录。单页前端 + 零依赖 Node 后端，数据全部存在自家 NAS 的 JSON 与附件目录里，局域网内任意设备打开同一地址看到的都是同一份数据。

当前部署地址：`http://192.168.5.132:8999`（容器 `grades-track`，8999 → 3000，开机自启）。安卓客户端是 WebView 壳，页面更新后无需重装 App。

## 目录结构

```
grades-track/
├── docker-compose.yml          # 主方案：免构建，直接用 node:20-alpine 挂载本目录
├── docker-compose.build.yml    # 可选：构建成自己的独立镜像
├── Dockerfile                  # 可选构建用
├── server.js                   # 后端：静态托管 + 数据读写 + 密码鉴权（零第三方依赖）
├── package.json
├── public/
│   ├── index.html              # 前端页面（已去掉资料库的托管脚本，可独立运行）
│   ├── avatar.jpg              # 学生头像（320×320 头部照，替换同名文件即可换头像）
│   └── daily-ledger.json       # 日常账本只读数据（10,641 笔，1.5MB，与成绩数据分开）
├── android/                    # 安卓 WebView 客户端（标准 Gradle 工程 + 已签名 APK）
│   ├── app/src/main/           #   MainActivity.java / AndroidManifest.xml / 图标
│   ├── build_apk.py            #   免 Android Studio 的一键构建脚本
│   └── dist/                   #   构建产物 FamilyHub-v2.0.0.apk
└── data/                       # 持久化目录：
    ├── grades.json             #   成绩 + 花销 + 压岁钱 + 日常账本增量 + 笔记本 { rev, data }
    ├── auth.json               #   密码哈希与登录令牌，容器启动后自动生成
    ├── attachments.json        #   试卷附件与凭证索引，容器启动后自动生成
    └── attachments/            #   试卷 PDF / 图片二进制文件
```

后端接口全部由零依赖的 `server.js` 提供：

- 成绩与账目：`GET/PUT api/state`、`POST api/login`、`POST api/password`、`GET api/health`。带 `rev` 版本号，两台设备同时编辑时后提交的会被拒绝并提示刷新，不会静默覆盖。
- 试卷附件：`GET/POST/DELETE api/attachments`、`GET api/file?id=...`。附件独立存盘，不写入 `grades.json`，也不参与 `rev`。

### 3. 笔记本（新模块）
类似华为 / 荣耀备忘录的随手记录：

- 富文本编辑器：加粗、斜体、下划线、删除线、标题、项目符号、编号、引用、分割线、链接、清除格式；可插入图片（自动压缩到 1000px JPEG 后内联保存）。
- 普通笔记 / 待办清单 / 日记三种类型；待办可逐项勾选并显示完成进度。
- 分类（可增删改名，重命名会同步该分类下所有笔记）、标签、8 种颜色、置顶、收藏、全文搜索、卡片 / 列表视图。
- 编辑时自动保存到 NAS，支持单篇导出 Markdown、整体导出 JSON；删除先进回收站，可恢复或彻底删除。
- 正文做了 HTML 白名单清理（去脚本、事件属性、`javascript:` 链接），导入外部备份不会执行脚本。笔记存在 `grades.json → notes`，随 JSON 备份一起导出。

### 4. 安卓 App v2.0.0
WebView 壳改名为「家庭事项记录」，默认服务器地址不变，首次启动可填私有服务器地址、顶部「服务器」可随时切换（家里内网 / 外面域名或穿透）。页面是服务端提供的，网页版更新后手机刷新即可，不需要重装。支持附件上传、凭证上传、导出到系统下载目录、返回键回退。安装包可从 `http://192.168.5.132:8999/FamilyHub-v2.0.0.apk` 直接下载。

### 5. Gitee 私有仓库

## 部署到飞牛 fnOS

> **当前状态：已部署完成。** 项目在 `/vol1/1000/docker/grades-track`，容器 `grades-track` 运行中，访问 `http://192.168.5.132:8999`。下面是复现 / 迁移步骤。
>
> 首次部署时飞牛默认的镜像加速 `docker.fnnas.com` 拉取超时，已改用 `docker.m.daocloud.io` 拉到 `node:20-alpine` 并标记为该名称；以后重建容器再遇到拉不动，见文末排错表。

### 方式 A：Docker 图形界面 / Compose（推荐，不用敲命令）

1. 用飞牛「文件管理」把整个 `grades-track` 文件夹上传到 NAS，例如 `/vol1/1000/docker/grades-track`（以你的实际存储路径为准）。
2. 打开飞牛桌面的 **Docker** 应用 → **Compose / 项目**（部分版本叫「编排」）→ 新建项目。
3. 项目目录选刚才上传的 `grades-track`，或直接粘贴 `docker-compose.yml` 的内容。
4. 点「启动 / 部署」，首次会自动拉取 `node:20-alpine` 镜像，稍等片刻。
5. 浏览器打开 `http://192.168.5.132:8999`。

### 方式 B：SSH 一键（最省事，需先在飞牛「设置 → 终端 / SSH」开启 SSH）

```bash
cd /vol1/1000/docker/grades-track     # 换成你上传的实际路径
docker compose up -d
docker compose logs -f                # 看到「成绩轨迹已启动」即可，Ctrl+C 退出日志
```

### 方式 C：不用 compose，只跑一条命令

```bash
docker run -d --name grades-track --restart unless-stopped \
  -p 8999:3000 \
  -e TZ=Asia/Shanghai \
  -v /vol1/1000/docker/grades-track:/app \
  node:20-alpine node /app/server.js
```

### 可选：打成独立镜像

```bash
docker compose -f docker-compose.build.yml up -d --build
```
这种方式只把 `data/` 挂载出来，升级代码需要重新 build 镜像。

## 试卷附件（v1.2 新增）

「成绩录入」页每一科（含总分）右侧都有「试卷」按钮，点开可上传、预览、删除该科的试卷 PDF 或图片。

- 支持 PDF / JPG / PNG / WEBP / GIF / HEIC，单个文件 ≤ 20MB，可一次选多个。
- 文件存在 NAS 的 `data/attachments/`，索引是 `data/attachments.json`，**不写入 `grades.json`**，所以导出的成绩备份不会变臃肿，多设备也不会因传附件触发 `rev` 冲突。
- 新增考试时先分配考试 ID，因此**点「保存考试」之前就能先传试卷**；删除考试会自动清理对应附件。
- 附件接口同样需要登录；服务端校验文件头，把 HTML 改扩展名伪装成 PDF 会被拒绝。
- 本地浏览器模式（未连后端）下附件功能不可用，页面会给出提示。

- **数据位置**：容器 `/app/data/grades.json`，对应宿主机 `grades-track/data/grades.json`。定期复制这个文件就是最可靠的备份。
- **页面内备份**：「设置与数据」→ 导出 JSON 备份 / 导出成绩 CSV；「花销记账」→ 导出收支明细 CSV。
- **试卷附件要单独备份**：附件在 `data/attachments/` 目录 + `data/attachments.json` 索引，两个都要复制。页面「导出 JSON 备份」只含成绩与账目，不含附件文件。
- **把另一台电脑上的旧数据搬过来**（重要）：资料库里那版页面是纯静态托管，成绩存在**那台电脑的浏览器里**，不会自动同步。请在旧电脑打开旧页面 →「设置与数据」→ **导出 JSON 备份**，再到 NAS 版页面 → **导入 JSON 备份**。这一步做完，两台电脑就统一到 NAS 数据了。
- **多设备**：手机、平板、其它电脑连同一局域网访问 `http://192.168.5.132:8999` 即可，不需要各自导出导入。
- **忘记密码**：删除 `data/auth.json` 后重启容器，密码恢复为 `meimima`；`grades.json`（成绩）完全不受影响。`auth.json` 由容器内 root 创建，SSH 下若提示无权限，用 `docker exec grades-track rm /app/data/auth.json && docker restart grades-track`。

## 改配置

| 想改什么 | 改哪里 |
| --- | --- |
| 对外端口 | `docker-compose.yml` 里 `8999:3000` 的左边；改完 `docker compose up -d` |

## 排错

| 现象 | 处理 |
| --- | --- |
| 页面显示「本地浏览器模式」 | 后端没连上。确认是用 `http://<NAS IP>:8999` 打开、容器在运行、`docker compose logs` 无报错 |
| 一直提示「需要密码」 | 先试初始密码；改过密码就用新密码。忘记密码见上文 |
| 提示「数据已在其它设备更新」 | 另一台设备刚改过数据，按提示刷新页面再编辑，避免覆盖。本次升级把 `rev` 往后推了一位，旧标签页保存时也会提示，**刷新即可** |
| 「保存失败：无法连接 NAS」 | 容器挂了或网络断了，先导出一份 JSON 备份再排查 |
| 端口 8999 被占用 | 换一个未占用端口，例如 `5789:3000` |
| 提示 `docker.fnnas.com ... i/o timeout` | 飞牛默认镜像加速不通。手动拉可用源并标记：`docker pull docker.m.daocloud.io/library/node:20-alpine && docker tag docker.m.daocloud.io/library/node:20-alpine node:20-alpine`，再 `docker compose up -d` |
| 容器起不来、报权限错 | 确认 NAS 上传目录对容器可读可写；`docker compose logs` 看具体报错 |
| 附件上传失败 / 提示格式不支持 | 只支持 PDF 与常见图片；确认文件真实格式（只改扩展名无效），单个 ≤ 20MB |
| 附件预览打不开 | 浏览器拦截了新窗口，允许本站弹窗即可；或检查 `data/attachments/` 里的文件是否被手动删除 |
| 点图表分项没反应 | 页面还是旧版缓存，按 `Ctrl+F5` 强制刷新；服务端已设 `Cache-Control: no-cache`，刷新即可拿到新版 |

## 安全提醒

- 这个服务面向**局域网/内网**使用，没有 HTTPS 和账号体系，只有一道密码。不要直接把 8999 端口映射到公网。
- 确实需要外网访问时，建议走飞牛的反向代理 + HTTPS + 强密码，或仅限 VPN / 内网穿透访问。
- `data/auth.json` 存的是 scrypt 加盐哈希和登录令牌，不含明文密码；不要把它提交到公开仓库。

按「投入小 / 用得上」排序，供后续迭代挑选：

1. **家庭总览首页**：一个跨模块的家庭 Dashboard，同屏显示最近一次成绩变化、本月学生花销、本月家庭支出、未完成的待办和最近笔记。

8. **自动备份与版本历史**：每天把 `grades.json` 快照打包，保留最近 30 天，支持一键回滚到某天。

10. **票据 OCR 与查重**：上传凭证时识别金额/日期自动填表，并提示重复报销。
